# TrustLens AI — Machine Learning Documentation

This document describes the models, datasets, training gates, inference behaviour and honest limitations present in this repository. It is based on checked-in artifacts and source code; it does not assume a live deployment, additional labelled data, external credentials, or network access during training. The authoritative runtime registry is `backend/models/model_manifest.json`.

## Dataset provenance

### Real job-description corpus: EMSCAD

The legacy job models are trained from `backend/data/raw/emscad_v1.csv`. The manifest records the training machine's absolute path; the repository-relative path above is the file present in this working tree.

| Property | Recorded value |
| --- | --- |
| Dataset name | `emscad_v1` |
| Origin | University of the Aegean EMSCAD corpus, CC0-origin Kaggle mirror |
| License note | CC0-origin; redistribution and modification permitted |
| Raw rows | `17,880` |
| Invalid labels dropped | `0` |
| Short text dropped | `0` |
| Duplicate normalized texts removed | `2,180` |
| Rows after cleaning | `15,700` |
| Class counts after cleaning | `0` legitimate = `14,993`, `1` fraudulent = `707` |
| `real_world_data` / `production_grade` in manifest | `true` / `true` |

`production_grade` is a provenance marker, not a guarantee of production accuracy. EMSCAD is an English job-posting benchmark corpus, not a stream of live user reports.

`load_emscad_dataset()` accepts `f`/`t` plus common boolean variants, requires a `fraudulent` label column, requires at least 20 rows per class, and combines `title`, `company_profile`, `description`, `requirements` and `benefits`. Text is normalized before de-duplication, so identical normalized postings cannot appear in both training and evaluation; near-duplicates can remain.

### Real deception corpus: DIFrauD

`backend/app/ml/datasets/difraud.py` reads a locally downloaded DIFrauD tree. It does **not** call Hugging Face at training or inference time; the corpus is an optional, out-of-band input.

| Property | Recorded value |
| --- | --- |
| Dataset | `difraud/difraud` |
| Source URL | <https://huggingface.co/datasets/difraud/difraud> |
| Revision marker | `main` |
| License | MIT |
| Requested message domains | `phishing`, `sms` |
| Requested job domain | `job_scams` |
| `real_world_data` / `production_grade` in manifest | `true` / `false` |
| Local path | `backend/data/datasets/difraud/<domain>/{train,validation,test}.jsonl` |

Only the requested domains are read. The loader uses DIFrauD's own train/validation/test splits, drops duplicate normalized texts within each split, removes validation/test texts already present in training, and verifies that every split has two classes. Threshold selection uses validation only; reported metrics come from the untouched test split.

Provenance recorded per model includes dataset name, source URL, revision, license, domains, source file paths and SHA-256 hashes, raw row counts, class counts, a fingerprint, PII handling notes and explicit benchmark limitations. The training summary's top-level `data.difraud_provenance` reflects the last loaded family; each artifact bundle records its own domains.

**PII and safety handling:**

- Raw JSONL is **not committed**. `backend/data/datasets/` is gitignored.
- Raw samples are never logged.
- `normalize_text()` replaces URLs, emails, phone numbers and digit runs with sentinel tokens before training.
- `scrub_personal_data()` additionally preserves the email domain while redacting the local part and replacing phone-like digit sequences.
- Residual personal data, malicious links and third-party labels may still remain; the cleaned corpus must stay outside version control.

No Hugging Face, Transformers or Torch dependency was added. Training remains TF-IDF plus scikit-learn `joblib` bundles.

### Synthetic recruitment-message corpus

`backend/app/ml/datasets/synthetic_messages.py` contains hand-authored email/SMS/WhatsApp-style examples. It is explicitly marked **not real-world**, **not production-grade** and for internal evaluation only. Ambiguous and incomplete examples are excluded from supervised training by default.

`message_tfidf_logreg` is trained and evaluated from this corpus for auditability, but it is rejected by the provenance gate and is not loaded at runtime. The approved `message_difraud_logreg` family is preferred when present.

### Anomaly feature provenance

The anomaly models are trained on cleaned EMSCAD rows using a fixed 24-feature vector from `backend/app/ml/features.py`. Text-derived signals (length, urgency terms, payment terms, personal-data terms, capital ratio and similar) come from postings. Metadata signals such as missing salary, missing logo, missing questions and telecommuting come from EMSCAD columns.

Contextual signals such as domain age, reputation, company age, scam reports and sender-domain mismatch are **absent from EMSCAD** and are set to neutral zeroes during training. The manifest records that runtime values from upstream lookups are unvalidated for those models.

## Preprocessing and splitting

### Text normalisation

`normalize_text()` is shared by training and inference to avoid train/serve skew. It:

1. Applies Unicode NFKC normalization.
2. Unescapes HTML entities and strips HTML tags.
3. Replaces URLs, email addresses, phone numbers and digit runs with `URLTOKEN`, `EMAILTOKEN`, `PHONETOKEN` and `NUMTOKEN`.
4. Lowercases text, removes punctuation and collapses whitespace.

The intent is to let models learn the presence of contact channels and numeric patterns rather than memorise specific addresses or numbers.

### Vectorisation and classifiers

`_text_pipeline()` builds a `scikit-learn` pipeline whose TF-IDF vectorizer is fitted on the training split only.

| Setting | Value |
| --- | --- |
| N-grams | `(1, 2)` |
| `min_df` | `2` for EMSCAD and DIFrauD runs; `1` for small synthetic runs |
| `max_df` | `0.95` |
| `max_features` | `30,000` |
| `sublinear_tf` | `True` |
| `strip_accents` | `unicode` |
| `lowercase` | `True` |

| Family | Classifier configuration |
| --- | --- |
| `job_tfidf_logreg` | `LogisticRegression(max_iter=2000, class_weight="balanced", C=1.0)` |
| `job_tfidf_linearsvc` | `LinearSVC(C=0.5, class_weight="balanced", max_iter=5000)` |
| `message_tfidf_logreg` | Same logistic-regression pipeline with `min_df=1` |
| `message_difraud_logreg` | Same logistic-regression pipeline on DIFrauD `phishing` + `sms` |
| `job_difraud_logreg` | Same logistic-regression pipeline on DIFrauD `job_scams` |

LinearSVC scoring applies a sigmoid to the clipped decision margin and flags it as a ranking score, not a calibrated probability. That artifact is approved but is not currently called by `TextPredictor.predict_job()`.

### Splits and thresholds

`stratified_split()` uses `RANDOM_SEED = 42` and a 60% train / 20% validation / 20% test split for EMSCAD and the synthetic corpus. DIFrauD uses its published split files. For the cleaned EMSCAD corpus:

| Split | Rows |
| --- | ---: |
| Train | `9,420` |
| Validation | `3,140` |
| Test | `3,140` |

`select_threshold()` chooses thresholds on the **validation split only**. It considers observed scores and a grid from `0.05` to `0.95`, keeps candidates with precision at least `0.35` and false-negative rate at most `0.30`, then minimizes FNR with F1 as a tie-break. If no candidate qualifies, it maximizes F1 with FNR as a tie-break. Degenerate single-class splits return `0.5`.

## Model selection and approval gates

Training is per family rather than a champion/challenger tournament. There is no code that automatically selects one winner across families and no human sign-off step. A family is written as `approved: true` only if every applicable gate in `_approval()` passes.

Common hard blockers:

- `provenance.real_world_data` is not `true` — synthetic-only models can never be promoted.
- ROC-AUC below the family minimum.
- Recall below the family minimum.
- False-negative rate above the family maximum.
- Precision below `0.15`.
- False-positive rate above `0.40`.
- Test support below `100`.
- Degenerate single-class evaluation split.

`production_grade` is recorded but is not an approval gate. DIFrauD is `real_world_data=true` and `production_grade=false`: it can pass the real-data gate while its research-benchmark limitations remain explicit.

| `job_tfidf_logreg` | `0.70` | `0.35` | `0.70` | Approved |
| `job_tfidf_linearsvc` | `0.70` | `0.35` | `0.70` | Approved |
| `message_difraud_logreg` | `0.70` | `0.35` | `0.70` | Approved |

## Inference flow

### Runtime loading

`TextPredictor` in `backend/app/ml/inference/predictor.py`:

1. Reads `MODEL_DIR/model_manifest.json`.
2. For a requested family, keeps manifest entries with `approved is True`, prefers `active is True`, and selects the newest `model_version` lexically.
3. Loads the referenced `joblib` bundle and verifies that the bundle payload itself has `approved: true`.
4. Caches successfully loaded artifacts for the predictor lifetime.
5. Returns a deterministic rule fallback if the manifest is missing/unreadable, no approved entry exists, an artifact fails to load, or inference raises.

`_candidate_entry()` compares `model_version` (not a legacy `version` key), so multiple approved versions are resolved chronologically.

Family preference is explicit:

| Call | Preference order | Behaviour when no approved family loads |
| --- | --- | --- |
| `predict_job(text)` | `job_difraud_logreg` → `job_tfidf_logreg` | `job_text_rule_fallback` |
| `predict_message(text, channel)` | `message_difraud_logreg` → `message_tfidf_logreg` | `message_text_rule_fallback` |
| `predict_offer(text, category)` | Rules only | `offer_rule_fallback` |
| `predict_anomaly(features)` | `anomaly_iforest` → `anomaly_supervised` | `anomaly_rule_fallback` |

A failed or missing DIFrauD artifact therefore falls back to the legacy approved family rather than degrading straight to rules. Generic offers never borrow recruitment-text models.

Fallback names end in `_rule_fallback`, the version is `rule-fallback-1.0`, and limitations explicitly say that no trained model was used and the rule scores are unvalidated heuristics.

### Analysis orchestration

`AnalysisService.run()` performs the end-to-end flow:

1. Check plan quota and optional idempotency by `client_request_id`.
2. Read the user's `consent_external_lookups` flag.
3. Parse documents without executing file content and extract entities.
4. Call predictors by input type:
   - `offer`: `predict_offer()` → `offer_rule_fallback`.
   - `job`, `document`, `monitoring`: `predict_job()` with the preference above.
   - `message`, `job`, `document`: `predict_message()` with the preference above.
   - Structured anomaly features: `predict_anomaly()` with the preference above.
5. Apply consent-gated external URL/domain/brand/company lookups.
6. Build rule indicators, de-duplicate them by name and persist them.
7. Call `score_risk()` with model predictions, indicators and available intelligence.
8. Persist the completed result, consume one scan, and notify on scores of at least 60 when notification delivery is configured.

Short normalized inputs are handled explicitly. With an approved model, fewer than three normalized words returns `inconclusive`; in fallback mode, fewer than four words returns `inconclusive`.

### Confidence, probability and risk score

- `fraud_probability` is a legacy field name for the model's fraud-oriented score used by the risk engine. For logistic regression it comes from `predict_proba`; for LinearSVC and several anomaly paths it is a sigmoid-mapped decision score. Present it as an **uncalibrated model risk score**, never as a calibrated fraud probability.
- `confidence` is a margin/evidence-strength indicator computed from distance to `0.5` and capped at `0.95`. It is **not** a calibrated probability and is **not** the risk score.
- `score_risk()` combines model scores with message, domain, company, history, brand, threat and community indicators. It discounts fallbacks (`0.45` trust), inconclusive predictions and synthetic claims, takes the strongest non-overlapping sub-signal inside each category, then normalizes weights over available categories only.
- Default weights are `content` `0.30`, `url` `0.25`, `brand` `0.25`, `threat` `0.10`, `community` `0.10`, normalized at runtime. `RISK_WEIGHT_*` environment variables override them; legacy six-weight variables are ignored.
- Risk bands are `0–19 Low observed risk`, `20–39 Limited warning signals`, `40–59 Moderate risk`, `60–79 High risk`, `80–100 Critical risk indicators`, configurable through `RISK_BAND_*_MAX`. Low coverage sets `inconclusive=True` and suppresses reassuring language.

## Explainability

Each prediction returns `model_name`, `model_version`, `prediction`, `fraud_probability`, `confidence`, `contributing_features` and `limitations`.

| Source | Explanation mechanism |
| --- | --- |
| Approved text models | Top five signed TF-IDF × linear-coefficient terms with `increases_risk` / `decreases_risk` direction |
| Approved anomaly models | Top five features by absolute `value × model weight` with direction from the sign of the product |
| Rule fallbacks | Explicit lexicon or feature-hit descriptions such as “Rule fallback matched high-risk phrase …” |
| Risk assessment | `evidence_summary`, `recommended_actions`, `confidence`, `uncertainty`, `component_scores`, `signal_weights`, `unavailable_signals`, `data_coverage`, `weights_version`, `inconclusive` and category summary |
| Source provenance | Timestamped `evidence_sources` with honest statuses and engine detail |

These are feature attributions and heuristics. They show what moved a score in this implementation; they are not causal explanations, proof of fraud, or independent verification.

## Retraining

The CLI entrypoint is `backend/scripts/train_models.py`. From the repository root:

```powershell
.\.venv\Scripts\python.exe backend/scripts/train_models.py --data-dir backend/data --model-dir backend/models
```

```bash
python backend/scripts/train_models.py --data-dir backend/data --model-dir backend/models
```

| Flag | Behaviour |
| --- | --- |
| `--data-dir` | Dataset directory; EMSCAD at `raw/emscad_v1.csv`, optional DIFrauD at `datasets/difraud/<domain>/*.jsonl`. |
| `--model-dir` | Destination for `joblib` artifacts, `*.meta.json` and `model_manifest.json`. |
| `--log-level` | Python logging level; defaults to `INFO`. |
| `--no-difraud` | Skip the optional DIFrauD corpus and train legacy families only. |
| `--message-domains` | Comma-separated DIFrauD domains for the message family; default `phishing,sms`. |
| `--job-domains` | Comma-separated DIFrauD domains for the job family; default `job_scams`. |

Example with explicit domains:

```powershell
.\.venv\Scripts\python.exe backend/scripts/train_models.py --data-dir backend/data --model-dir backend/models --message-domains phishing,sms --job-domains job_scams
```

`train_all()` cleans data, trains every family, applies approval gates, writes versioned artifacts and metadata, rewrites `model_manifest.json`, and prints a JSON summary. Rejected artifacts remain on disk for audit. The CLI does not pass a `Repositories` instance, so it does not register models in the database registry.

A retrain does not hot-reload a running API. Restart/redeploy the API and verify the manifest version before treating a retrained model as live.

## Monitoring and drift recommendations

These are recommendations only; this repository does not implement a production model-monitoring or drift-detection pipeline.

- Record manifest `training_version`, `model_name`, `model_version`, prediction, score, fallback flag, latency, analysis type, language if known, risk score and data coverage with each served prediction.
- Track score distributions and bands over time; alert on sudden shifts or collapsing variance.
- Track fallback rate by family. A non-zero generic-offer or anomaly fallback rate is expected; an increase in approved job/message fallback indicates a manifest or artifact problem.
- Segment by channel, source and length. DIFrauD `phishing`/`sms`/`job_scams` labels are curated for general deception; cross-domain and cross-language generalization is unvalidated.
- Use `POST /api/v1/reports/feedback` labels as a review queue, not automatic ground truth.
- Re-evaluate precision, recall, FNR and FPR on genuinely labelled held-out data before changing thresholds. Never tune thresholds on test data.
- Monitor operational health: request errors, p95 latency, quota refusals, webhook failures, database availability and queue depth.

## Honest limitations

- Text-only models do not independently verify an offer, brand, employer, domain, sender or campaign.
- EMSCAD models are English-language job-posting classifiers. DIFrauD models are English-language research-benchmark classifiers. Other languages and regions are unvalidated.
- DIFrauD is `real_world_data=true` but `production_grade=false`. Its labels are curated for general deception research, not verified against TrustLens production traffic.
- DIFrauD `phishing` + `sms` training uses a permissive threshold with a `0.3746` FPR; false positives are expected.
- DIFrauD `job_scams` has a `0.2069` FNR; false negatives are expected.
- Direct identifiers are redacted but residual personal data or malicious links may remain in the excluded raw corpus.
- There is no general-offer model. `predict_offer()` is rule-only by design.
- The anomaly models are rejected, and their contextual features were neutral zeroes in EMSCAD training.
- High ROC-AUC coexists with modest precision. A positive score warrants review, not an accusation.
- `fraud_probability`, LinearSVC sigmoid output, anomaly sigmoid output and `confidence` are not calibrated probabilities.
- `job_tfidf_linearsvc` is approved in the manifest but is not currently called by inference.
- No fairness, bias, adversarial-robustness, multilingual, calibration or external-validation study is present.
- Feature attributions and rule hits are not causal explanations.
- Rejected and synthetic-corpus metrics are audit information, not product performance claims.
- Retraining changes files but does not automatically update a running process or container image.

## Prohibited claims

Do not state or imply any of the following:

- “The system detects all scams” or “guarantees fraud detection”.
- “99% accurate”, “near-perfect” or any headline accuracy derived only from ROC-AUC.
- That DIFrauD is production-verified data or that `production_grade=false` models are production-grade.
- That synthetic message metrics are production KPIs.
- That message or anomaly ML models are all rejected; the DIFrauD message and job families are approved when bundled and loadable.
- That `job_tfidf_linearsvc` is used by current inference.
- That `confidence`, `fraud_probability` or a sigmoid-mapped margin is a calibrated probability.
- That the risk score is a model confidence value or a calibrated probability of fraud.
- That a low score proves an offer, posting, brand, sender or link is legitimate.
- That a text model independently verifies employers, domains, senders or campaigns.
- That the platform supports languages or channels beyond what has been evaluated.
- That the system is certified, legally compliant, bias-free or a substitute for human review.
- That a retrained model is live before the API is restarted/redeployed and the manifest version is verified.
